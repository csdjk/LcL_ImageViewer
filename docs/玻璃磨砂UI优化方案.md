# 玻璃磨砂 UI 优化方案

> 本文记录基于 `b99efcc` 的原始优化方案和验收规范。方案之后的实现与当前验收状态请以 `docs/status.md`、`docs/task-board.md` 和 Git 为准。

## 1. 目标与证据边界

目标：保留悬浮、沉浸、轻量的看图体验，让工具栏和面板有柔和的磨砂厚度，同时提高文字清晰度、操作准确性与布局稳定性。

建议视觉方向：**中性烟灰玻璃 + 少量鼠尾草绿强调**。浅色对应中性乳白玻璃；绿色主要用于选中、焦点和开关，不作为整个看图画布的明显色罩。

本轮交付为基于截图和源码的优化规划。基线提交为 `b99efcc`，审查时 Git 工作区干净。没有修改应用 UI 或渲染代码，没有执行新界面的运行截图验收。

- 用户截图为 1154×1058 物理像素，实际客户区、Windows 缩放率和 egui pixels_per_point 未知，不能把截图像素直接当成布局单位。
- 实际技术栈为 Rust、egui/eframe 0.27、wgpu 0.19；以下尺寸均为 egui 逻辑点，物理像素按运行时 pixels_per_point 转换。
- 使用 ui-ux-pro-max 的 Glassmorphism 风格检索、文字对比度检索与通用检查表。该技能没有 egui 栈条目，具体实现建议来自本项目源码分析；不套用 CSS backdrop-filter 或移动端尺寸规则。
- 用户截图用于审查旧界面，不是要求新界面保持 98% 相似的目标稿。后续如确定目标设计图，再按同条件截图进行量化还原验收。

## 2. 当前问题与代码证据

| 优先级 | 问题 | 证据与影响 | 优化方向 |
|---|---|---|---|
| P0 | 玻璃采样内容不完整 | `image.wgsl::fs_main` 在图片范围外 discard；模糊采样对象仅为图片纹理，棋盘格在模糊之后合成 | 对 UI 下方已经合成的画布做统一模糊，覆盖图内、图外及透明区域 |
| P0 | 同一效果存在两套尺度 | 桌面背景是低分辨率快照高斯模糊；面板下图片为约 18 物理像素半径的 25 点采样；背景设置不控制面板模糊 | 分清“画布背景”和“面板磨砂”，面板半径改为统一逻辑单位 |
| P0 | 小字偏暗、选中文字偏浅 | 提示与通道标签使用 `faint`；RGB 选中底色直接使用较浅 accent | 提升正常文字对比度，并为选中底色定义独立文字色 |
| P1 | 轮廓比材质更显眼 | `capsule` 叠加整圈描边，`paint_glass_sheen` 再画固定截断的水平亮线 | 弱化外轮廓，让高光沿圆角连续渐隐，加入低幅面内明暗变化 |
| P1 | 工具条拥挤，控件大小不统一 | 图标按钮 28×26，图标 16；通道为默认 selectable，徽章、文字各自分配高度 | 统一 32×32 操作区、图标绘制框与文本垂直对齐规则 |
| P1 | 顶栏缺少可靠宽度预算 | 单行持续追加 Mip、动画、HDR 控件；文件名按 28 个字符截断 | 按实际字体测宽，分配弹性文件名区域和明确的溢出入口 |
| P1 | 底栏空闲时仍很长 | `draw_bottom_overlay` 始终按含四个浮点通道的最长样本预留空间 | 默认只展示坐标、HEX、缩放；详细读数放入可固定的检查器 |
| P1 | 按下、悬停、键盘焦点区分不足 | `icon_btn` 合并 hover/down 的绘制分支，没有单独绘制焦点环 | 补齐五种交互状态，操作过程中禁止自动隐藏 |
| P1 | 自动隐藏缺少键盘焦点条件 | `update_overlay_visibility` 检查鼠标、弹层等状态，没有显式的控件焦点条件 | 纳入焦点和键盘操作，提供固定工具栏设置 |
| P2 | 全窗桌面磨砂更新与截图有冲突风险 | `app.rs::update` 周期抓取并临时设置截图排除；有等待与拖动节流 | 单独验证拖动、截图、最小化和捕获失败；不把增加捕获频率作为材质优化方法 |

截图中央的大片暗色与局部模糊，可能与原图、桌面快照或当前设置有关；没有取得相同输入与运行状态，不能据此判定图片未加载或整幅图片被错误模糊。

### 配色的已核算证据

按标准 sRGB 相对亮度公式，对代码中的不透明颜色进行理论对比度计算：

| 组合 | 比值 |
|---|---:|
| 深色 faint `#5C6A61` / canvas `#202724` | 2.68:1 |
| 浅色 faint `#9AAAA0` / canvas `#DCE7DF` | 1.92:1 |
| 浅色 dim `#6D7F74` / canvas `#DCE7DF` | 3.35:1 |

这些是配色风险证据，不是对用户截图的实际文字对比度测量。最终必须测量玻璃与底图合成后的背景，不能只看色板。

## 3. 视觉规范初值

以下是首轮调试起点，最终值由实际运行截图和局部检查决定。

| 项目 | 建议 |
|---|---|
| 间距节奏 | 4 / 8 / 12 / 16 / 24 |
| 顶部安全距离 | 16；最大化、全屏和最小窗口单独检查 |
| 顶栏高度 | 48：32 高控件 + 上下各 8 |
| 顶栏圆角 | 24，圆头区域不放紧贴边缘的控件 |
| 容器左右内边距 | 12；最后一个按钮实际绘制区域距外缘至少 12 |
| 按钮 | 操作区 32×32；图标 16–18；内圆角 9–10 |
| 图标笔画 | 统一约 1.5 逻辑点，按实际 DPI 检查清晰度和光学重量 |
| 同组 / 跨组间距 | 4 / 12；分隔线只用于少数真正的功能边界 |
| 文件名 / 普通标签 | 13–14；属性正文 14；辅助文字不低于 12 |
| 数字 | 使用现有等宽字体；固定数据槽，避免位数变化推挤邻项 |
| 底部状态条 | 高 36、距底 16、圆角 18、默认宽约 420，按窗口可用宽度收缩 |
| 弹层 | 圆角 16、内容内边距 20、分组间距 16、操作按钮高 32 |

字体沿用现有 Segoe UI、微软雅黑、Consolas。字体更换不是本轮重点，先统一使用规则，修正中英文混排的视觉中心。中文提示用比例字体，坐标与 RGBA 数值用等宽字体。

### 材质分层

从后向前的顺序为：**模糊后的真实画布内容 → 中性调色层 → 轻微面内明暗 → 连续边缘高光 → 控件与文字**。阴影位于面板轮廓外。

| 参数 | 深色初值 | 浅色初值 |
|---|---|---|
| 画布基础色 | `#171A1C` | `#E6E8E7` |
| 面板调色 | `#24292C`，约 72% | `#F5F7F6`，约 82% |
| 设置/菜单调色 | 深色面板色，约 86% | 浅色面板色，约 90% |
| 主文字 | `#F1F4F3` | `#25312C` |
| 次文字/有效提示 | `#B6C0BB` | `#53635A` |
| 强调色 | `#9FCAB4` | `#356C52` |
| 深色选中块文字 | `#16271F`，配浅绿实色选中底 | — |
| 模糊半径 | 面板约 16 逻辑点，设置弹层约 20 | 同左，独立调试可读性 |
| 外描边 | 白色约 10%–14%，1 物理像素 | 深中性约 12%–16%，1 物理像素 |
| 顶缘高光 | 白色约 16%–20%，沿圆角渐隐 | 白色约 45%–60%，沿圆角渐隐 |
| 外投影 | y=6，blur=20，黑色约 24% | y=5，blur=18，黑色约 12% |
| 接触阴影 | y=1，blur=3，黑色约 12% | y=1，blur=3，黑色约 7% |

约束：玻璃上不添加装饰性彩虹、光团或强烈折射，不给待查看图片加色罩。默认不加颗粒；仅在平坦渐变实测出现色带时，评估固定、低幅抖动，并限定在面板内。

## 4. 顶栏和底栏布局

### 顶栏：一个外壳，分清四组职责

正常宽度排列：

`打开 · 上一张/计数/下一张 | 文件名 / 格式 | RGB R G B A · 视图工具 | 主题 · 设置 · 窗口控制`

- 文件名是主要信息，格式徽章弱化；尺寸移入底栏或属性面板，减少竞争。
- 文件名根据当前字体真实测宽进行中间省略，保留扩展名；悬停和键盘聚焦时能看到完整名称。
- RGB/R/G/B/A 做成一个 32 高的分段控件，选择底块统一高度，文字按实际字形居中。选中有形状和文字色差，不能只改一个绿字。
- 图标沿用当前矢量绘制体系，校正齿轮、太阳、适配、1:1 的光学大小；不要混入字体字符或 emoji。
- 最近邻不能只靠四宫格图标猜含义，Tooltip 清楚写“像素采样：最近邻 / 平滑”；保留快捷键。
- 最小化/最大化/关闭始终有固定空间，关闭按钮仅悬停或按下使用危险色。
- 空白拖动区域和按钮命中区域互斥；窗口拖动、双击最大化与按钮双击分别验证。

### 宽度策略

优先用“实际可用宽度减去固定操作区”分配布局；以下区间只作为初始布局档位，不能替代字体测量。

| 逻辑窗口宽度 | 策略 |
|---|---|
| ≥1200 | 完整通道分段、视图操作、弹性文件名；类型专属控件有足够空间才放主条 |
| 1000–1199 | 缩短文件名槽，次级格式信息进入属性；主题入口可移入更多菜单 |
| 880–999 | 保留打开/导航/文件名/当前通道/适配/更多/窗口控制；通道展开为菜单 |

动画、HDR、Mip 的专属工具在空间不足时进入顶栏下方的上下文工具条，不依赖极小字号硬塞进主条。上下文工具条跟随主条显隐；加载不同格式时不挪动窗口控制位置。

### 底栏：简洁读数，按需展开细节

- 默认显示像素色块、坐标、HEX 和右侧缩放比例；未指向图像时显示可读提示。
- 默认和取样状态共用当前布局档位的固定宽度，不随光标移动伸缩。
- 小数 RGBA、原始浮点值、Mip 等详细信息放入明确可打开/固定的检查器，保留专业查看能力。
- RGB 数值与原始浮点值始终来自现有图像数据，不能从带玻璃效果的屏幕结果重新取样。
- 长读数可选择或复制；窄窗口优先保留坐标、HEX、缩放，其他字段在检查器中完整显示。

## 5. 交互与弹层

| 状态 | 表现和行为 |
|---|---|
| 默认 | 清晰图标，透明按钮底 |
| 悬停 | 约 100ms 进入轻微亮底，Tooltip 保留功能名和快捷键 |
| 按下 | 与悬停不同的底色/内轮廓，立即反馈，不改变控件尺寸或文本位置 |
| 选中 | 明确底块 + 独立前景色；与悬停叠加后仍可识别 |
| 键盘焦点 | 可见焦点环；Tab 顺序符合从左到右的布局，Enter/Space 可操作 |
| 禁用 | 降低视觉强调并关闭触发；需要时提示不可用原因 |

自动隐藏保留沉浸行为，建议静止等待由 1.6s 调至约 2.4s；淡入约 120ms、淡出约 180ms，避免长时间停留在半透明、难读状态。鼠标悬停、按住控件、键盘焦点、菜单/设置打开、错误待处理时保持可见。提供“固定工具栏”，支持减少动效。

设置与属性窗口使用同一玻璃材质，更高的不透明度用于保障阅读。建议设置宽约 400，超过客户区高度时内容滚动，标题、关闭按钮和必要操作保持可达。仅真正阻塞操作的对话框使用遮罩，非模态属性窗口不增加全屏遮罩。

设置文案区分：

- “面板磨砂”：影响工具栏、菜单、属性和设置的材料。
- “画布背景”：纯色 / 棋盘格 / 桌面磨砂的适用关系要明确；棋盘格仍是透明图片区域的衬底。
- 桌面磨砂的说明面向用户写“柔化窗口后方内容”；捕获失败的诊断细节放日志，设置中显示可理解的不可用状态。
- 保留用户现有背景偏好，不因本轮视觉调整覆盖持久化设置。

## 6. 渲染实现路线

### 统一面板下面的画布

建议流程：

1. 将画布背景、透明衬底和已按当前通道/曝光转换的图片合成为一张不含 UI 的场景纹理。
2. 场景纹理保持当前图片显示逻辑；先建立无玻璃区域的像素回归基线，验证颜色空间、Alpha、最近邻和 HDR 不变。
3. 对场景纹理生成降采样模糊纹理，初版使用可分离水平/垂直模糊；按场景变化刷新，空闲缓存。
4. 屏幕先绘制清晰场景，再在统一圆角遮罩内采样模糊结果，最后由 egui 绘制面板调色、边缘、图标和文字。
5. 面板位置、圆角、淡入淡出共享同一份几何数据，避免遮罩与面板一帧错位或尺度不同。

实现注意：

- `ImagePaintCmd::paint` 当前接收已经打开的 RenderPass。离屏合成与模糊应安排在与锁定版本兼容的 prepare/资源准备阶段，不能在 paint 内嵌套 RenderPass；进入实现前核对本地依赖源码的回调生命周期。
- 模糊针对已正确合成的画布；透明输入须正确处理预乘 Alpha，避免透明像素颜色产生暗边/彩边。
- 明确纹理格式、sRGB 转换和 HDR tonemap 次序，避免色彩转换两次。
- 半径、几何遮罩和边缘羽化统一按 pixels_per_point 转换，覆盖 100%/125%/150%/200% DPI。
- 图片、缩放、位移、通道、曝光、动画帧或背景快照变化时使场景缓存失效；只改变面板悬停色不需要重建整个场景。
- 初版只分配一组共享中间纹理，不为每个胶囊分配整窗纹理；窗口变化才重建尺寸相关资源。
- 弹层重叠时先保证对共同画布的采样一致，用遮挡与不透明度表达层级；不扩展成任意递归背景模糊系统。
- 现有 MAX_GLASS=6 必须覆盖实测同时存在的浮层；超限不能无声地让部分面板失去材质。

### 桌面背景链路

保留为独立能力。当前代码注释记录了 DWM 材质在既有组合下未生效的历史观察，这不等于已经证明所有 wgpu/Windows 组合均不支持原生磨砂，本轮不据此更换窗口后端。

先修正可观察性：记录捕获失败原因，检查 GDI 资源和截图排除恢复结果，复用背景纹理。拖动期间的更新必须验证错位、跳变与延迟，不能靠更多等待或更频繁排除截图掩盖问题。

截图验收应优先捕获应用自身渲染结果；如果使用窗口捕获，必须检测整窗被排除或空白的情况。不能把抓到的桌面背景误认为应用截图。

## 7. 实施顺序与修改范围

| 阶段 | 修改位置 | 完成门禁 |
|---|---|---|
| A：建立基线与材质样板 | 本地 UI 验证入口；`render.rs`、`image.wgsl` | 固定输入和 DPI 的基线截图；一块面板跨越图片、透明区和画布边缘时材质一致 |
| B：统一组件外观 | `ui.rs` 的 Palette、capsule、sheen、icon_btn、标签/分段控件 | 深浅两套主题，主次文字清晰，边缘无硬截断；默认/悬停/按下/选中/焦点截图合格 |
| C：布局与信息层级 | `app.rs` 顶栏/底栏/显隐/设置/属性/菜单 | 最小窗口无溢出、按钮不贴边；长文件名、动画、Mip、HDR 均有可用入口 |
| D：完整回归 | `backdrop.rs` 及相关生命周期；截图与性能验证 | 图片显示与取样回归、桌面捕获恢复、DPI、多窗口状态、性能预算全部有证据 |

保持解码库和文件关联逻辑在本轮范围之外。以这四阶段分别形成可检查的 diff，出现新失败才扩大排查范围。

## 8. 验收矩阵与性能预算

验收运行对象为实际 Windows 桌面应用，不用 HTML 样稿替代。现有 `ui-verify-shots/capture_final.py` 含旧机器目录、固定 HWND 和鼠标移动代码，只能作为历史参考，不可原样运行。

运行截图必须记录：应用构建标识、客户区物理尺寸、逻辑尺寸、pixels_per_point、Windows 缩放率、输入图片标识、主题、背景模式、页面与交互状态。路径使用项目忽略的 `ui-verify-shots/`，临时比较产物放 `Temp/`。

| 维度 | 必测范围 |
|---|---|
| 主题 | 深色、浅色 |
| 尺寸 | 880×560、1280×860、1920×1080 逻辑客户区；结合显示器实际能力安排，无法运行的组合明确记录 |
| DPI | 100%、125%、150%、200%；重点检查一像素边缘、中英文居中和文件名截断 |
| 输入 | 暗图、亮图、高饱和图、透明 PNG、黑白棋盘、HDR、多 Mip DDS、动画 |
| 几何关系 | 面板在图内、图外、跨图片边缘、图像平移/缩放经过面板 |
| 交互 | 默认、悬停、按下、选中、禁用、键盘焦点、隐藏/显现、固定工具栏 |
| 面板与边界 | 设置、属性、右键菜单、错误、空态、加载；长中文/英文名称与长错误文案 |
| 窗口 | 普通、最大化、全屏、拖动、缩放、最小化恢复；桌面背景开启/关闭、捕获失败 |

不用全量笛卡尔积；先在标准尺寸覆盖全部功能状态，再在窄窗口和各 DPI 覆盖最容易溢出及混排的状态。每轮调整后重截受影响状态。

视觉门禁：

- 普通主次文字在合成背景上的对比度目标 ≥4.5:1，具有语义的图标与焦点指示目标 ≥3:1；分别验证深浅主题和亮/暗背景。
- 按实际字体渲染检查水平/垂直中心、基线、裁切和中英文长度变化；几何中心只能作为初值。
- 弹窗逐项检查屏幕边距、面板内边距、标题/正文/图标/关闭与操作按钮间距、主次按钮层级。小窗口也必须可关闭、可操作。
- 无面板的图片显示保持基线一致；取样数值不受材质影响。模糊只出现在定义的面板遮罩内。
- 有目标设计稿时，固定输入、状态、视口、DPI 和裁剪范围，以有效比较区域的归一化 RGBA 像素相似度 `1 - Σ|实际值-参考值| / (255 × 通道数 × 像素数)` 达到 ≥98%，输出对比、叠加与差异图；动态排除区域必须记录理由。整体通过后仍检查局部缺陷。
- 没有目标稿时不宣称 98% 相似；没有实际运行截图时不宣称 UI 已完成。

性能目标是待测预算：先记录当前相同场景的基线，再比较修改后的中位数与 P95。交互目标 60fps，面板合成与模糊新增 GPU 时间争取 ≤2ms；若平台不支持 GPU 计时，明确采用 CPU/呈现帧间隔作为代理，不能标成 GPU 实测值。空闲时不因玻璃装饰维持连续重绘。

资源估算示例：1920×1080 RGBA8 场景纹理约 7.91 MiB，加两张四分之一宽高的模糊纹理约 0.99 MiB，总计约 8.90 MiB；不含原图、交换链、驱动额外分配。高 DPI 按物理尺寸重新预算，若使用其他纹理格式重新计算。
