# v0.7.1 — 修复大动画无法打开

本版修复 v0.7.0 中有效动图因解码后全部帧超过 256 MiB 而被拒绝打开、并误报为“不支持的格式”的问题。这个大小指展开后的像素量，不是压缩文件大小。

## 更新内容

- **大动图自动缓存**：GIF、APNG、动态 WebP 和 AVIF 共用新的帧存储方式。小动画仍使用内存；较大动画自动转入本机私有临时文件并只读映射，不再要求整段像素全部保存在堆内存中。
- **保持完整画质与动画**：不缩小分辨率，不截断帧序列，保留原始透明度和帧时长。播放、暂停、前后逐帧、取色及当前帧编辑继续使用原始 RGBA。
- **自动清理与明确提示**：缓存最后一个引用释放后自动删除，不修改原图。临时目录权限、磁盘空间及资源限制错误会显示明确原因，不再伪装成格式不支持。
- README、便携版说明及新增依赖的许可文件已同步更新。此前的 OCR、主画布编辑、通道检查、置顶和背景调色板保留。

## 使用提示

首次打开仍需完成动画解码，较大的动画需要系统临时目录有可用空间；慢速磁盘可能影响载入和分页读取。64 MiB 是帧数据转存阈值，**不是整个进程的内存上限**，解码器、GPU 和系统文件缓存另计。

保留安全边界：单动画最多 4096 帧、展开数据最多 8 GiB，单帧 RGBA 最多 256 MiB；本进程临时帧文件总预算 16 GiB。不会静默降低分辨率或丢帧。缩略图仍只读取首帧。
